# forum_required_tag 插件说明文档（版块强制 Tag + 标题前缀）

- **插件名**：`forum_required_tag`（版块强制 Tag）
- **版本**：1.0.0
- **兼容**：FlintHub 1.0（SplitDB 分片引擎）
- **依赖**：无（纯钩子实现，零核心侵入）

---

## 一、插件概述

### 1.1 定位

为需要规范化发帖的版块提供两类**强制约束**：

1. **强制 Tag**：管理员为版块预设"允许的 Tag 列表"，用户在该版块发帖/编辑时，必须从预设列表中选择一个 Tag，否则无法提交；
2. **标题前缀**：管理员为版块预设"标题前缀列表"，用户在该版块发帖/编辑时，标题必须以预设前缀开头（如 `[求助] 我的问题`），否则无法提交。

两个功能相互独立：版块可只开强制 Tag、只开标题前缀，或同时开启；未配置任何约束的版块，行为与未安装插件完全一致（**零影响**）。

### 1.2 设计原则

- **不侵入核心**：不修改 `app/` 下任何文件，仅通过核心钩子（Hook）工作；
- **插件独立库**：所有数据存于 `plugins/forum_required_tag/data/forum_required_tag.sqlite`（`Plugin::db('forum_required_tag')`），不动核心业务库；
- **前端零内联**：样式/JS 全部收敛到插件 `assets/`，不修改核心视图模板与样式表；
- **多语言**：zh / en / zh_tw 三语同步，键前缀 `plugin.forum_required_tag.*`。

## 二、功能清单

| 功能 | 说明 | 后台入口 |
|---|---|---|
| 强制 Tag 管理 | 为版块增删 Tag、启用/禁用、排序 | Tab 1 |

## 三、技术架构

### 3.1 钩子清单（plugin.json）

| 钩子名 | 钩子文件 | 职责 |
|---|---|---|
| `init_after` | `hook/init_after.php` | 独立库幂等建表兜底 |
| `admin_route_register` | `hook/admin_route_register.php` | 后台路由（已带 `/admin` 前缀组内，注册相对路径） |
| `route_register` | `hook/route_register.php` | 前台配置接口路由 `/api/forum-required-tag/config` |
| `route_before_dispatch` | `hook/route_before_dispatch.php` | **核心校验**：发帖/编辑帖提交前强制 Tag + 前缀校验 |
| `thread_create_after` | `hook/thread_create_after.php` | 发帖成功后写使用记录 |
| `thread_edit_after` | `hook/thread_edit_after.php` | 编辑成功后更新使用记录 |
| `layout_head_end` | `hook/layout_head_end.php` | 发帖/编辑页输出 `meta[frt-base]` + 直出配置 + assets |

> **关键设计**：核心不存在 `thread_create_before` / `thread_edit_before` 等"提交前"钩子（已 grep 核实），因此**校验拦截改走 `route_before_dispatch`**（路由分发前钩子，`mod_system` 插件同款拦截先例），在核心写入前完成校验；记录则放在 `_after` 钩子（此时 `thread_id` 才存在）。

### 3.2 数据表（SQLite 独立库，3 张表）

```sql
-- 版块 × 强制 Tag 绑定
frt_forum_tags (
    id INTEGER PRIMARY KEY,
    forum_id INTEGER NOT NULL,        -- 版块 ID（category_id）
    tag_name TEXT NOT NULL,
    sort_order INTEGER DEFAULT 0,
    enabled INTEGER DEFAULT 1,        -- 启用/禁用开关
    created_at TEXT NOT NULL,
    UNIQUE(forum_id, tag_name)
);

-- 版块 × 标题前缀绑定（prefix 存储不含方括号，展示/校验为 [xxx]）
frt_forum_prefixes (
    id INTEGER PRIMARY KEY,
    forum_id INTEGER NOT NULL,
    prefix TEXT NOT NULL,
    sort_order INTEGER DEFAULT 0,
    enabled INTEGER DEFAULT 1,
    created_at TEXT NOT NULL,
    UNIQUE(forum_id, prefix)
);

-- 发帖/编辑使用记录
frt_post_tags (
    id INTEGER PRIMARY KEY,
    thread_id INTEGER NOT NULL,
    forum_id INTEGER NOT NULL,
    tag_name TEXT DEFAULT '',        -- 实际使用的 Tag（未配置强制 Tag 时为空串）
    prefix TEXT DEFAULT '',          -- 实际使用的标题前缀
    user_id INTEGER NOT NULL,
    created_at TEXT NOT NULL
);
-- 索引：idx_frt_forum_tags(forum_id, enabled)、idx_frt_forum_prefixes(forum_id, enabled)、
--       idx_frt_post_tags(thread_id)、idx_frt_post_tags_forum(forum_id, created_at)
```

### 3.4 核心校验流程（route_before_dispatch）

```
① 非 POST 请求 → 直接放行（读操作零开销）
② 剥离 BASE_PATH 后解析路径：
   - POST /post/new（发帖）        → forum_id = $_POST['category_id']
   - POST /thread/{id}/edit（编辑） → forum_id = $_POST['category_id']（优先，用户可能改版块）
                                      └ 未携带时回退 (new Thread())->getById() 取旧版块
   - 其余路径 → 直接放行
③ 目标版块未配置任何强制项 → 直接放行（0 影响）
④ 校验：
   - 强制 Tag：提交 tags 的第一个必须命中预设列表（编辑帖 tags 为空时用帖子原有 Tag 参与校验）
   - 标题前缀：标题必须以 [某预设前缀] 开头
⑤ 失败 → 422 + 独立错误页（views/error.php，含错误文案 + 返回按钮）
⑥ 通过 → 放行，核心正常写入；记录由 _after 钩子完成
```

### 3.5 前台提示的两种加载方式

| 场景 | 加载方式 |
|---|---|
| 带分类进入发帖页（如版块页点发帖 `?category_id=3`）/ 编辑页 | `layout_head_end` 服务端**直出** `#frt-config` 数据容器，首屏即有提示 |
| 未选分类进入发帖页 | `script.js` 监听 `select[name="category_id"]` 变化 → `fetch('/api/forum-required-tag/config?forum_id=N')` **懒加载** |
| 切换分类 | 无论是否有直出，均重新拉取新版块配置并刷新提示（无配置自动清空） |

提示条/前缀选择器由 `script.js` **动态创建**并插入到对应输入框旁（`input[name="tags"]` / `input[name="title"]`），不依赖任何 head 内占位元素、不修改核心视图。

## 四、后台使用指南

后台入口：插件管理页 → "版块强制 Tag"（`/admin/forum-required-tag`，需管理员二次验证）。

### Tab 1：强制 Tag 管理

> 用户在该版块发帖时，必须从预设列表中选择一个 Tag，否则无法提交。

1. 顶部下拉**选择版块**；
2. 输入 Tag 名（≤30 字符）点击"添加"（同名重复自动拒绝）；
3. 列表每行：**启用/禁用开关**（停用则该校验不生效但配置保留）、**删除**按钮；
4. **一键复制**：选择"从版块"与"复制到"，把源版块全部 Tag 复制到目标版块（重复项跳过）。

### Tab 2：标题前缀管理

> 用户在该版块发帖时，标题必须以预设前缀开头（如 `[求助]`），否则无法提交。

1. 选择版块；
2. 输入前缀名（≤20 字符，无需方括号，如 `求助`；自动按 `[求助]` 校验）点击"添加"；
3. 每行：启用/禁用开关、删除；
4. 一键复制（同 Tab 1）。

### Tab 3：使用记录

> 展示各版块发帖时实际使用的强制 Tag / 标题前缀记录，可筛选与删除。

- 按版块筛选、分页浏览（帖子 ID / Tag / 前缀 / 发帖人 / 时间）；
- 单条删除。

## 五、前台交互说明

### 5.1 发帖页（post/create）

- 版块配置了强制 Tag：标签输入框下方出现提示条——`本版块需选择 Tag： [电脑软件] [手机app]`，**点击标签即可填入输入框**（支持多选，逗号分隔；再次点击取消），当前选中项高亮；
- 版块配置了标题前缀：标题输入框下方出现前缀选择器，点击 `[求助]` 自动拼入标题头部（再次点击移除，切换前缀自动去旧）；
- 未预选分类时：选择分类后提示条/选择器自动出现。

### 5.2 编辑帖（thread/edit）

- 同样强制校验与提示；编辑页预填的已有 Tag 自动高亮；
- 用户改版块时：校验按**新版块**规则（服务端与前端一致）。

### 5.3 拦截体验

校验失败 → `422` 独立错误页（提示具体原因 + 返回按钮）。**设计取舍**：拦截属"强制校验"而非表单校验，不重定向回填已填内容（回填列入后续优化）。

## 七、验证与测试

1. **语法**：全部 PHP 文件 `php -l` 零错误；UTF-8 无 BOM + LF；
2. **缓存**：改动 plugin.json 的 hooks 清单后需重建 `plugins/plugins_cache.json`（删除或 `Plugin::refresh()`）；
3. **激活**：后台激活 → 独立库 3 表 + 4 索引创建成功；
4. **后台配置**：为版块 A 添加 Tag/前缀；重复添加被拒；开关切换；复制到版块 B；
5. **发帖测试**：版块 A 不选 Tag → 422 拦截；选预设 Tag 无前缀 → 拦截；带 `[求助]` 前缀 + 预设 Tag → 成功，记录写入；未配置版块 → 不受影响；
6. **编辑测试**：移除 Tag/去掉前缀 → 拦截；保持 → 成功；改版块 → 按新版块规则；tags 留空但有原 Tag → 用原 Tag 校验放行；
7. **懒加载**：未选分类进发帖页 → 无提示；选择分类 → 提示条/前缀选择器出现；切换分类 → 刷新；
8. **卸载自检**：卸载后 3 表删除、`Plugin::getPlugin('forum_required_tag')` 返回 null。

## 八、常见问题

**Q1：为什么校验放在 `route_before_dispatch` 而不是 `thread_create_before`？**
核心不存在任何 `_before` 发帖钩子（只有 `thread_create_after` 等 `_after` 钩子），`route_before_dispatch` 是核心唯一的路由分发前拦截点（mod_system 插件同款先例），能在核心写入前完成校验。

**Q2：编辑帖改了版块，按哪个版块校验？**
按 `$_POST['category_id']`（用户提交的新版块）校验；未携带时才回退路径帖子的旧版块。用户从"无约束版块"改到"有约束版块"同样会强制。

**Q3：扩展名/前缀是否允许重复？**
同一版块内不允许（`UNIQUE(forum_id, tag_name)` / `UNIQUE(forum_id, prefix)` 兜底），不同版块互不影响。

**Q4：停用某个 Tag 后，已发布的帖子受影响吗？**
不影响历史数据；仅后续发帖/编辑校验不再允许选择该 Tag（编辑时若帖子仍带该 Tag 且已停用，会被拦截，需先改为启用中的 Tag）。

**Q5：为什么删除 `views/editor_hint.php`？**
早期版本在 `</head>` 前输出 div 占位，会被浏览器渲染到页面顶部（导航上方出现提示条）；现改为 `script.js` 动态创建提示元素，占位文件不再需要。
