## 一、总则：三条硬性安全规则

> 这三条是**铁律**，任何插件代码（钩子、控制器、模型、Plugin.php）都必须遵守。
> 给 Agent 下指令时，直接抄这三段即可。

### 规则 1：文件操作，无 basename 不落盘

任何涉及 `unlink()`、`file_get_contents()`、`file_put_contents()`、`move_uploaded_file()` 的插件代码，必须遵循以下模板：

```php
$safeName = basename($userInput);
if (!$safeName || $safeName !== $userInput) { /* 拦截：非法文件名 */ }
$safePath = rtrim(UPLOAD_PATH, '/') . DIRECTORY_SEPARATOR . $safeName;
if (is_file($safePath)) { unlink($safePath); }
```

**铁律：凡是文件名，一律先过一遍 `basename()`，不允许直接拼接用户输入的字符串。** 只有这样，插件才能彻底摆脱"路径穿越"的隐患。

### 规则 2：数据库查询，无预处理不执行

任何涉及 SQL 的操作，必须采用 `prepare()` + `bindValue()` 或 `execute([':id' => intval(...)])`，坚决杜绝字符串拼接：

```php
$stmt = $db->prepare("DELETE FROM `table` WHERE `id` = :id");
$stmt->execute([':id' => (int)$_POST['id']]);
```

**铁律：所有查询，必须带参数绑定或 `(int)` 强转。** 审计中扫出的 IDOR 报错，就是因为有些地方直接拼了 ID。

### 规则 3：所有入库/出库字符串，必须过 htmlspecialchars() 或 strip_tags()

`TemplateCompiler` 本身已做 `$this->e()` 的自动转义，但插件的控制器和模型层也要自觉做到：

```php
$safeTitle = htmlspecialchars($inputTitle, ENT_QUOTES, 'UTF-8');
$safeContent = strip_tags($content);
```

**铁律：凡是输出到页面上的文字，绝不能绕过 `$this->e()` 或 `htmlspecialchars()`。**

## 一五、最高级别红线（8 条，一票否决）

> 以下 8 条为**最高级别红线**，与第一章三条硬性规则同级，任何插件代码违反任一条件直接判定不合格。
> 给 Agent 下指令时，把本节整体附上。

### 红线 1：严禁反序列化与动态执行

禁止使用 `unserialize()`（统一用 `json_decode($data, true)`）、`eval()`、`assert()`、`preg_replace('/e')`。核心已明确"改用 json 避免 unserialize RCE"（`app/Models/Category.php`），插件同样适用。

### 红线 2：严禁滥用绝对路径

所有路径必须基于 `__DIR__` 或 `BASE_PATH` 常量拼接，严禁使用 `$_SERVER['DOCUMENT_ROOT']`。插件目录内引用统一 `__DIR__ . '/../xxx'`；URL 统一 `$bp`（BASE_PATH）拼接。

### 红线 3：禁止在渲染钩子中断页面

视图/渲染类 Hook（`layout_head_end`、`controller_view_before`、`footer_links`、`nav_*` 等）内**绝不能**使用 `die()` / `exit()` / `header()`，必须 `return;` 返回。渲染钩子在布局输出过程中执行，中断会毁掉整页或产生"headers already sent"。

### 红线 4：上传文件必须白名单 + 随机文件名

必须强制扩展名白名单（如 `['jpg','png','gif']`），保存时重命名为**强随机文件名**，禁止保留原始文件名：

```php
$ext = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION));
if (!in_array($ext, ['jpg','png','gif'], true)) { /* 拒绝 */ }
$filename = bin2hex(random_bytes(16)) . '.' . $ext; // 强随机，勿用 md5(microtime+rand) 弱随机
```

> 推荐直接复用核心 `\app\Helpers\Upload::file()`（已内置白名单 + MIME 校验 + `random_bytes` 随机名）。

### 红线 5：数量扣减必须原子更新

涉及库存/积分扣减，必须用原子 UPDATE 并检查 `rowCount()`，**严禁先 SELECT 再 UPDATE**（并发下超卖/超扣）：

```php
$stmt = $db->prepare('UPDATE pm_products SET stock = stock - 1 WHERE id = :id AND stock > 0');
$stmt->execute([':id' => $productId]);
if ($stmt->rowCount() === 0) { /* 库存不足，回滚/拒绝 */ }
```

### 红线 6：IN (...) 查询必须强转 + 占位符

ID 数组必须 `intval` 强转 + 生成占位符，**严禁 `implode` 拼 SQL**：

```php
$ids = array_map('intval', $ids);
$in = implode(',', array_fill(0, count($ids), '?'));
$stmt = $db->prepare("SELECT * FROM t WHERE id IN ({$in})");
$stmt->execute($ids);
```

### 红线 7：PDO 不得覆盖核心异常模式

`Plugin::db()` 返回的 PDO 已由 `DBFactory` 统一设置 `PDO::ERRMODE_EXCEPTION` + `PDO::ATTR_EMULATE_PREPARES=false` + `PRAGMA busy_timeout=5000`。插件**不得覆盖**这些属性；SQLite 无 `PDO::ATTR_TIMEOUT` 语义，超时走 `busy_timeout`（已默认 5000，如需调整用 `PRAGMA busy_timeout = N`）。

### 红线 8：AJAX 请求必须带 CSRF Token

所有异步 POST 必须携带 CSRF Token——**表单体 `csrf` 字段**（代码库惯例，`hx-vals` / `FormData` 携带）或 `X-CSRF-Token` 请求头均可；服务端必须 `Csrf::verifyOrDie()` 校验。禁止无 CSRF 的写操作 AJAX。

## 二、插件目录结构

**一目录一插件**：每个插件独立目录，目录名即插件名（小写下划线，如 `points_mall`）。

```
plugins/{插件名}/
├── plugin.json          # 插件配置（必填，含 hooks 清单）
├── Plugin.php           # 插件主类：activate/deactivate/uninstall + 业务数据方法（可选但推荐）
├── FrontController.php  # 前台控制器（可选，路由指向它）
├── AdminController.php  # 后台控制器（可选，后台路由指向它）
├── hook/                # 钩子文件（plugin.json 中 hooks 指向的文件）
│   ├── init_after.php
│   ├── route_register.php
│   ├── admin_route_register.php
│   └── ...
├── views/               # 插件视图（view('plugins/{插件名}/xxx') 解析到这里）
│   ├── admin.php
│   └── index.php
├── assets/              # 插件静态资源（Web 可直接访问）
│   ├── style.css
│   └── script.js
├── lang/                # 插件语言包（自动合并，无需钩子）
│   ├── zh.php
│   ├── en.php
│   └── zh_tw.php
└── data/                # 插件独立数据库（由 Plugin::db() 自动创建）
    ├── {插件名}.sqlite
    ├── .htaccess        # 自动生成：禁止 Web 访问
    └── web.config       # 自动生成：IIS 禁止 Web 访问
```

**禁止**：
- 在插件目录放 `.bak`、`.revert`、`.tmp` 等残留文件（审计曾发现 content_review 残留 4 个 `.bak`、invite 残留 `.revert`）。
- 在插件目录外（核心目录）写任何文件。
- 修改核心文件（`app/`、`assets/css/admin.css` 等）——插件样式/JS 必须收敛到插件自己的 `assets/`。

## 三、plugin.json 配置规范

插件目录下必须有 `plugin.json`（UTF-8、合法 JSON、无 BOM）。字段如下：

```json
{
    "name": "积分商城",
    "version": "1.0.0",
    "author": "FlintHub",
    "description": "积分商城：商品兑换（头衔/勋章/VIP/程序源码），支持防重复购买与冷却时间",
    "activated": true,
    "icon": "gift",
    "admin_url": "/admin/points-mall",
    "hooks": {
        "init_after": "hook/init_after.php",
        "route_register": "hook/route_register.php",
        "nav_plugin_links": "hook/nav_plugin_links.php",
        "layout_head_end": "hook/layout_head_end.php",
        "controller_view_before": "hook/controller_view_before.php",
        "admin_route_register": "hook/admin_route_register.php",
        "profile_user_card_after": "hook/profile_user_card_after.php"
    },
    "permissions": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 插件显示名（中文） |
| `version` | ✅ | 版本号，如 `1.0.0` |
| `author` | ✅ | 作者 |
| `description` | ✅ | 功能描述 |
| `activated` | ✅ | 是否启用（`true`/`false`） |
| `category` | 否 | 后台插件分类（`system`/`community`/`content`/`entertainment`），缺省归入 `default`（未分类） |
| `icon` | 否 | 后台/导航图标名（FontAwesome 语义名） |
| `admin_url` | 否 | 后台管理入口 URL |
| `hooks` | ✅ | 钩子清单：`"钩子名": "相对插件目录的钩子文件路径"` |
| `permissions` | 否 | 权限白名单声明，空数组表示无特殊权限；**强制模式默认开启（2026-09 起）**，未声明所需权限的操作会被 DENY（详见下） |

**坑（重要）**：
- **hooks 路径用 `/` 分隔**（如 `"hook/init_after.php"`），不要用 `\`。
- **插件注册/改动 hooks 后，必须手动更新 `plugins/plugins_cache.json`**（含 hooks 清单），否则钩子不生效。最简单的方式：删除 `plugins/plugins_cache.json` 让系统重建，或调用 `\app\Helpers\Plugin::refresh()`。
- `activated` 由系统在激活/禁用时自动写回，插件代码不要手动改。

**permissions 声明（2026-09 起强制生效）**：系统 `permission_enforce` 默认已置 `1`（强制模式）。插件调用受控能力但未声明对应权限时，操作被 **DENY**（不执行 + `error_log`），不再是"警告放行"：

| 插件能力 | 必须声明的权限 |
|---|---|
| 写全局设置（`activate()` 调 `Settings::update()` 等） | `"system:settings"` |
| 注册后台路由（`admin_route_register` 钩子） | `"route:admin"` |
| 发起外部 HTTP 请求（`Plugin::http()`） | `"net:fetch"` |

> 例：seo 插件 `activate()` 写全局设置但缺 `system:settings`，在强制模式下会被拒绝，已补声明（P2 M-3）。无后台入口的插件可保持 `[]`，但建议在 `plugin.json` 注释标注（如 notifications）。

## 四、插件主类 Plugin.php

插件主类提供：独立库连接、幂等建表 DDL、activate/deactivate/uninstall、业务数据方法。命名空间 `Plugin\{插件名}`（**首字母大写驼峰**，目录名小写下划线）。

```php
<?php
namespace Plugin\PointsMall;

class Plugin
{
    /** 插件独立库连接（plugins/points_mall/data/points_mall.sqlite） */
    public static function db(): \PDO
    {
        return \app\Helpers\Plugin::db('points_mall');
    }

    /** 建表 DDL（幂等） */
    public static function ddl(): string
    {
        return "CREATE TABLE IF NOT EXISTS pm_products (
            id INTEGER PRIMARY KEY,
            name TEXT NOT NULL,
            description TEXT NOT NULL DEFAULT '',
            points INTEGER NOT NULL DEFAULT 0,
            stock INTEGER NOT NULL DEFAULT 0,
            created_at TEXT NOT NULL
        )";
    }

    /** 激活：建表 + 索引（幂等） */
    public static function activate(): bool
    {
        \app\Helpers\Plugin::ensureSchema('points_mall', self::ddl());
        return true;
    }

    /** 禁用 */
    public static function deactivate(): bool
    {
        return true;
    }

    /** 卸载：删除数据表 */
    public static function uninstall(): void
    {
        self::db()->exec('DROP TABLE IF EXISTS pm_products');
    }
}
```

**约定**：
- `activate()` / `deactivate()` / `uninstall()` 是系统约定方法名，系统在激活/禁用/卸载时自动调用（无需手动触发）。
- `activate()` 返回 `false` 或抛异常 → 系统回滚激活状态（`plugin.json` 与内存都会回滚）。
- 建表用 `Plugin::ensureSchema($name, $ddl)`（幂等 `CREATE TABLE IF NOT EXISTS`），不要用 `SHOW TABLES LIKE` 探测。
- 数据方法建议做**运行时缓存**（静态属性），同一请求内避免重复查库。
- 建表 DDL 必须是 **SQLite 语法**（见第十节），禁止 `ENGINE=InnoDB`、`AUTO_INCREMENT`、`DATETIME`、`VARCHAR(n)` 等 MySQL 写法。

### 4.1 生命周期调用链（显式约定）

`activate()` / `deactivate()` / `uninstall()` 的调用顺序与依赖关系必须遵守：

```
激活：写 plugin.json(activated=true) → 调 Plugin::activate()（建表）
      └─ activate() 返回 false / 抛异常 → 系统回滚 activated=false（文件+内存），激活失败

禁用：写 plugin.json(activated=false) → 调 Plugin::deactivate()（可选清理，异常忽略）

卸载：调 Plugin::uninstall() → 写 plugin.json(activated=false) → 系统从缓存移除该插件
      └─ 顺序要求：先清插件独立库的表 → 再清核心库 settings/用户字段残留 → 最后（系统自动）重建 plugins_cache.json
```

**坑**：
- `activate()` 必须确保 `ensureSchema()` 建表成功再返回 `true`；若建表失败直接返回 `false` 或抛异常，让系统回滚——**不要**"建表失败但激活成功"。
- `uninstall()` 的清理顺序**不能反**：先删独立库表，再清核心库残留；`plugins_cache.json` 由系统 `saveCache()` 自动重建，**不需要也不应该**在插件里手动删。
- `deactivate()` 是"临时禁用"，**不要**删表（删表是 `uninstall()` 的职责），否则重新激活时数据丢失。

## 五、控制器与命名空间

### 5.1 命名空间与自动加载

插件类命名空间 `Plugin\{插件名}`（**首字母大写驼峰**，如 `Plugin\PointsMall`），由 `app/Core/Autoloader.php` 的 PSR-4 风格自动加载器解析，**无需手动 require_once**：

- `Plugin\PointsMall\Plugin` → `plugins/points_mall/Plugin.php`
- `Plugin\PointsMall\FrontController` → `plugins/points_mall/FrontController.php`
- 自动加载器支持驼峰转下划线（`FriendLinks` → `friend_links`）、全小写等路径尝试。

**坑**：
- 命名空间首字母大小写必须与实际文件一致（审计曾发现 `\Plugin\dev_docs\Plugin` 调用 `\Plugin\DevDocs\Plugin` 导致 404）。
- 路由钩子里**不要写冗余的 `require_once`**（如 `require_once __DIR__ . '/../FrontController.php'`）——自动加载器已处理，写了反而可能重复加载。现有插件有历史遗留，新插件不要学。
- **核心 Model 的 `find()` / `getById()` 是实例方法**：必须 `(new \app\Models\Thread())->find($id)` 调用，**禁止静态调用** `Thread::find()`——PHP 8 下抛 `Non-static method ... cannot be called statically`。Thread/Post/User/Category 均如此（ai_assistant 曾因此 worker 读主题全部失败，被吞成 "thread not found" 排查数轮）。

### 5.2 前台控制器

前台控制器继承 `app\Core\Controller`，用 `$this->view()`、`$this->json()`、`$this->redirect()`、`$this->requireLogin()` 等基类方法：

```php
<?php
namespace Plugin\PointsMall;

use app\Core\Controller;

class FrontController extends Controller
{
    public function index()
    {
        $this->requireLogin(); // 未登录自动跳转 /login（自动处理 BASE_PATH）
        $this->view('plugins/points_mall/shop', [
            'products' => \Plugin\PointsMall\Plugin::getProducts(),
        ]);
    }
}
```

**坑**：
- **登录检查用 `$this->requireLogin()`**，不要 `header('Location: /login'); exit;`（后者不处理 BASE_PATH）。
- 404 用 `$this->view('errors/404', [...])`，不要 `echo '<h1>404</h1>'; exit;`。
- 视图名统一 `plugins/{插件名}/{视图}`，解析到 `plugins/{插件名}/views/{视图}.php`。

### 5.3 后台控制器

后台控制器同样继承 `app\Core\Controller`，路由在 `hook/admin_route_register.php` 中注册（`$router` 变量由核心注入）：

```php
<?php
// hook/admin_route_register.php
if (!isset($router)) return;
$router->get('/points-mall', ['\Plugin\PointsMall\AdminController', 'index']);
$router->post('/points-mall/add', ['\Plugin\PointsMall\AdminController', 'add']);
```

后台视图用 `$this->section('css')` / `$this->section('content')` 组织（见第六节），并自行声明插件样式。

## 六、视图与模板

插件视图位于 `plugins/{插件名}/views/*.php`，使用与核心视图相同的模板机制（`TemplateCompiler`）。

### 6.1 区块组织

```php
<?php $this->section('title'); ?><?php echo $I('plugin.points_mall.shop_title'); ?> - <?php echo $this->e($this->getData('siteName')); ?><?php $this->endSection(); ?>
<?php $this->section('css'); ?>
<link rel="stylesheet" href="<?php echo \defined('BASE_PATH') ? BASE_PATH : ''; ?>/plugins/points_mall/assets/style.css">
<?php $this->endSection(); ?>
<?php $this->section('content'); ?>
<div class="mn-section pm-shop">
    ...
</div>
<?php $this->endSection(); ?>
```

- `section('title')`：页面标题
- `section('css')`：**页面级 CSS 在此声明**（布局 `yield('css')` 会输出）——这是插件页面加载样式的**首选方式**，比 `layout_head_end` 钩子更精准
- `section('content')`：页面主体

### 6.2 常用模板方法

| 方法 | 作用 | 坑 |
|---|---|---|
| `$this->e($str)` | HTML 转义输出（**必用**） | 禁止裸 `echo $var` |
| `$this->t('key')` | 多语言文案 | 见第八节 |
| `$this->url('/path')` | 生成带 BASE_PATH 的 URL | **所有前台链接必须用它**，禁止硬编码 `/xxx` |
| `$this->asset('css/xxx.css')` | 核心静态资源 URL（自动带版本号） | 只服务 `/assets/`，插件资源用 `/plugins/...` |
| `$this->icon('名称', 16)` | 输出 FontAwesome 图标 | **名称必须在 `app/Core/TemplateCompiler.php` 的 `$map` 中**，否则回退问号（如 cart 不存在要用 cart-shopping） |
| `$this->getData('key', $default)` | 读视图数据 | — |
| `$this->pagination($page, $total, $url)` | 分页条 | — |

### 6.3 视图数据注入

核心 `Controller::view()` 会注入公共变量：`currentUser`、`isLoggedIn`、`isAdmin`、`csrfToken`、`currentNav`、`__current_template`（当前模板名）等。插件可用 `controller_view_before` 钩子往 `$data` 注入额外数据（见第九节）。

### 6.4 前台 UI 一致性（图标/间距/容器/导航）

> 2026-09 user_level 会话沉淀：插件前台页面与核心 UI 必须保持"同一视觉语言"，否则下拉菜单、页面宽度、页内导航错位一眼可见。

## 七、资源文件 assets/

插件静态资源放 `plugins/{插件名}/assets/`，Web 可直接访问（`.htaccess` 只拦截 `plugins/*/data/`，不拦 assets）。

### 7.1 引用方式

```php
$bp = \defined('BASE_PATH') ? BASE_PATH : '';
// 资源加 filemtime 版本号：浏览器缓存旧版 CSS/JS 时强制拉新
$cssVer = @filemtime(__DIR__ . '/../assets/style.css') ?: 1;
echo '<link rel="stylesheet" href="' . $bp . '/plugins/points_mall/assets/style.css?v=' . $cssVer . '">';
```

**坑**：
- **资源路径必须拼 `BASE_PATH`**（二级目录部署否则 404）。
- **资源加 `?v=filemtime` 版本号**（插件资源不经 `asset()`，浏览器会缓存旧版）。
- **样式/JS 零内联**：CSS 收敛到 `assets/style.css`，JS 收敛到 `assets/script.js`，钩子文件里不要输出大段内联 `<style>/<script>`（审计曾发现 announcements/friend_links/invite 内联；细则与审计清单见 7.3）。
- 不要改核心 `admin.css` / `modern.css`。

### 7.2 按页面条件加载

插件资源**不要无条件全局加载**。两种方式：
1. 插件自有页面：在视图 `section('css')` 里声明（推荐）。
2. 需要注入核心页面（如帖子详情）：用 `layout_head_end` 钩子，且**按 `$template` 条件输出**（核心已传 `template` 参数）：

```php
// hook/layout_head_end.php
$tpl = $template ?? '';
if ($tpl !== 'thread/show') return; // 仅帖子详情页加载
$bp = \defined('BASE_PATH') ? BASE_PATH : '';
$cssVer = @filemtime(__DIR__ . '/../assets/style.css') ?: 1;
echo '<link rel="stylesheet" href="' . $bp . '/plugins/xxx/assets/style.css?v=' . $cssVer . '">';
```

### 7.3 样式/JS 零内联细则（2026-08-29 内联审计落地）

> 背景：2026-08-29 内联审计扫描全部插件 `views/`、`hook/` 与控制器，命中内联 `<script>` 块 9 处、内联 `on*` 事件属性 9 处、内联 `style=""` 属性 39 处。以下细则把"零内联"落成可执行清单，审计按此复查。

**P0 级（一票否决，审计必查）：**

1. **禁止内联 `<script>` 块**：页面内 `<script>...</script>` 逻辑一律迁入插件 `assets/script.js`，视图/钩子只保留 `<script src="...assets/script.js?v=filemtime">` 引用；**控制器禁止 PHP 字符串拼接输出 `<script>`**——htmx 片段需回填 DOM 时，改输出 `data-*` 属性，由外部 script.js 监听 `htmx:afterSwap` 读取并更新（参考 dice / quiz_duel 整改）。
2. **禁止内联 `on*` 事件属性**（`onclick/onchange/onsubmit/onload` 等）：一律在 `assets/script.js` 内 `addEventListener` 绑定；传参走 `data-*` 属性——单条数据可 `data-xxx='<?php echo htmlspecialchars(json_encode($row, JSON_HEX_TAG|JSON_HEX_AMP|JSON_HEX_APOS|JSON_HEX_QUOT), ENT_QUOTES, 'UTF-8'); ?>'`，JS 端 `JSON.parse` 读取（参考 announcements 的 `data-ann`、friend_links 的 `data-link`、medal 的 `data-medal`）。理由：规避 CSP `script-src` 内联限制与 XSS 风险面。

**P1 级（规范一致，审计必查）：**

3. **禁止 `style=""` 属性写静态样式**（边距/字号/宽度/去下划线等）：收敛为 `assets/style.css` 的 class，优先复用核心工具类（`mn-mt-*`/`mn-mb-*` 间距、`mn-maxw-*` 宽度、`mn-fs-*` 字号、`mn-text-decoration-none`、`mn-flex-wrap`）。
4. **动态色值**（徽章/状态/图标背景/边框）：两种合规做法二选一——
   - 预定义色板 class：如 `points_mall` 的 `pm-badge-*`、`content_review` 的 `cr-noti-circle-approve/reject`；
   - 内联 CSS 变量注入：`style="--xxx-bg:<?php echo $s['bg']; ?>;"` + class 内 `background: var(--xxx-bg, 默认色)`。**内联 CSS 变量注入属合规做法**（参考 `medal` 的 `--mn-medal-color`），审计不视为违规。
5. **`display:none` 显隐**：统一改 class（`.xxx-hidden`）或 Alpine `x-cloak`（`assets/style.css` 补 `[x-cloak] { display: none !important; }`），消除硬编码 `style="display:none;"`（参考 announcements / friend_links / medal / content_review 弹窗整改）。
6. **i18n 文案注入 JS**：禁止内联 `<script>window.XxxI18n = {...}</script>`，改 data 属性承载 JSON：`<div id="xxxI18n" hidden data-i18n='<?php echo htmlspecialchars(json_encode(...), ENT_QUOTES, 'UTF-8'); ?>'></div>`，script.js 启动时 `JSON.parse` 读取（参考 icon_generator 整改）。

**P2 级（发布前检查，必做）：**

7. 发布前跑一次零内联检查，应零命中（`<script src>` 引用除外）：
   ```
   grep -nE '<style|<script>|on(click|change|submit|load)=' plugins/{插件名}/views plugins/{插件名}/hook
   ```
8. 双主题（浅色 + 暗夜星辰）走查被改页面。

## 八、语言包 lang/

插件语言包放 `plugins/{插件名}/lang/{语言}.php`，**自动合并**到核心语言包（`I18n::mergePluginLangs()`），无需写任何钩子代码。合并规则：**核心键优先，插件仅补充缺失键**（`$dict + $extra`）。

```php
<?php
// plugins/points_mall/lang/zh.php
return [
    'plugin.points_mall.title'      => '积分商城',
    'plugin.points_mall.shop_title' => '积分商城',
    'plugin.points_mall.empty'      => '暂无可兑换商品',
];
```

**约定**：
- 键名统一 `plugin.{插件名}.{语义}` 前缀，避免与核心/其他插件冲突。
- 至少提供 `zh.php`；`en.php`、`zh_tw.php` 建议同步。
- 视图里用 `$this->t('plugin.xxx.yyy')` 或 `\app\Helpers\I18n::get('plugin.xxx.yyy')` 读取；缺 key 回退中文 → key 本身，永不白屏。
- **前后台文案区分**：前台交互提示用 `*_act` 后缀（如 `err_points_act`），无后缀 `err_*` 是后台表单校验文案——曾多次用错，注意区分。

## 九、钩子系统全览

钩子由 `\app\Helpers\Plugin::hook($hookName, $params)` 触发：遍历所有**已激活**插件，若 `plugin.json` 的 `hooks` 中注册了该钩子，则 `include` 对应文件，并把 `$params` `extract()` 到钩子文件作用域。

**机制要点**：
- 钩子文件内可用 `$params` 展开的变量（如 `$router`、`$template`、`$data`…），也可访问 `$_SERVER`、`$_SESSION`、全局函数。
- 单个钩子出错不影响其他插件和页面继续运行（`error_log` 记录后继续）。
- 钩子文件路径有**路径穿越校验**（realpath 必须落在插件目录内）。
- 只有 `activated: true` 的插件钩子才会触发。

> ### ⚠️ `route_before_dispatch` 的双触发陷阱（必读小节）
>
> **本钩子在一次请求里会被触发两次**：`index.php`（路由注册完成后）一次，`app/Core/Router.php`（`dispatch()` 派发前）再一次。这是最高优先级红线之一，**不要**把它当成普通表格条目随手跳过。
>
> 而 `Plugin::hook()` 使用**裸 `include`**（不是 `include_once`）加载钩子文件，因此：
>
> **① 禁止在钩子文件中声明顶层函数/类/接口/trait**
> 否则第二次 include 会抛 `Fatal error: Cannot redeclare xxx()`。生产环境 `display_errors` 关闭时表现为**整站空白页 / 500**，且常规 CLI 测试（只 include 一次）**完全无法发现**。
>
> 必须声明时，用 `function_exists` / `class_exists` 包裹：
> ```php
> if (!function_exists('myHelper')) {
>     function myHelper() { /* ... */ }
> }
> ```
>
> **② 条件块内的声明不做提升（no hoisting），必须放在所有调用点之前**
> `if (!function_exists(...)) { function foo() {} }` 中的函数只有在执行流走到该 `if` 块时才被定义。若「先调用、后声明」会抛 `Fatal error: Call to undefined function foo()`——这是修复①时极易引入的次生 bug。
>
> 正确写法：把守卫块放在文件**顶部**（任何 `return` 短路与业务逻辑之前）。
>
> **③ 回归防线**：`php cli/_verify_plugin_hook_reinclude.php`
> 覆盖：逐钩子文件双 include 安全性、全仓 `hook/*.php` 顶层声明守卫普查、`Plugin::hook()` 连续触发两次端到端、核心触发路径确认、守卫写法正反例、顺序陷阱正反例与静态校验。
> **新增或修改任何 `route_before_dispatch` 钩子后，必须跑一次。**

> **约定（新插件）——后台不走侧边栏入口（必读）**：新插件**一律不注册 `admin_sidebar_links` 钩子**，后台入口统一通过 `plugin.json` 的 `admin_url` 字段提供（插件管理页点击进入），避免侧边栏堆积无关入口。**存量插件**（points_mall / announcements）若确有常驻侧边栏需求，才保留 `admin_sidebar_links`。

> **经验（来自 ai_assistant 开发）**：
> - **钩子名必须先 grep 核实，不能照需求/文档字面写**：需求写 `thread_created_after` / `reply_created_after`，核心实际是 `thread_create_after` / `post_create_after`（参数也不同）。开发前先 `grep "Plugin::hook('xxx'" app/` 确认钩子真实名称与注入参数。
> - **耗时/副作用逻辑慎用每页触发的全局钩子**：`route_after_dispatch` 每页触发，曾导致"浏览任何页面都可能触发 AI 消费"、行为不可预期。这类逻辑优先放业务钩子（`thread_create_after` 等）或控制器锚点（如后台 `index()` 内按 tab 判断），确需全局钩子时做管理员判断 + 触发源收敛，并配节流防抖。

### 9.2 钩子文件模板

```php
<?php
// hook/controller_view_before.php
$template = $params['template'] ?? '';
$data = &$params['data'];
if ($template !== 'thread/show') return; // 只处理需要的视图
// 往视图注入数据
$data['my_extra'] = '...';
```

**坑**：
- `$params` 中**引用类型参数**（如 `$data`）用 `&$params['data']` 解引用才能改到调用方数据。
- 钩子文件顶部**先判空/判模板**再干活，避免在无关页面白跑（性能）。
- 需要 `$router` 的钩子（`route_register` 等）先 `if (!isset($router)) return;`。
- 全局拦截类钩子（`auth_login_check`、`attachment_download_before`）通过 `$GLOBALS['xxx']` 置位与核心通信，**必须用约定好的全局变量名**。

## 十、独立数据库与事务

### 10.1 插件独立库

**每个插件一个独立 SQLite 文件**：`plugins/{插件名}/data/{插件名}.sqlite`。通过 `\app\Helpers\Plugin::db($name)` 获取（原生 PDO），自动创建 `data/` 目录并补写 `.htaccess`/`web.config` 防 Web 下载：

```php
$pdb = \app\Helpers\Plugin::db('points_mall'); // 原生 PDO
$stmt = $pdb->prepare('SELECT * FROM pm_products WHERE id = :id');
$stmt->execute([':id' => (int)$id]);
$row = $stmt->fetch(\PDO::FETCH_ASSOC);
```

**坑**：
- 插件自有表**必须**放独立库，**不要**写全局 `business.sqlite`（核心库只读访问保留给 seo 等只读插件）。
- 插件间不共享数据、互不依赖。
- `Plugin::db()` 返回的是**原生 PDO**，不是框架 `Database` 类——没有 `$db->query($sql, $params)` 那种便捷绑定，要自己 `prepare()`。
- **读核心帖子/博客数据必须经 Model，禁止直接查核心库 `threads`/`blogs` 表**：SplitDB 迁移后帖子已迁至 `main_index.topic_index`（分片），核心库 `threads` 表为 0 行（退役表）。seo 插件曾直接查 `threads` 表导致 SEO 帖子描述长期为空（见 `插件性能与索引审计报告.md`）。正确做法：经 `\app\Models\Thread` / `\app\Models\Blog` 读取，或按 SplitDB 分片规则查 `main_index.topic_index`。
- **批量补用户名/用户信息必须走 `\app\Models\User::batchGetNames($ids)` / `batchGetUsers($ids)`**（2026-09 新增，请求级缓存）：**禁止**直接 `SELECT id, username FROM users WHERE id IN (...)` 直查核心库 users 表——13 个存量插件（content_review/dice/floor_reply/quiz_duel 等）已统一改造（P2 M-1），新插件直接复用，避免 N+1 查询与核心库连接池压力。

### 10.2 事务

事务用 PDO 原生方法：`beginTransaction()` / `commit()` / `rollBack()`，**不是** `begin()` / `commit()`：

```php
$pdb = \app\Helpers\Plugin::db('points_mall');
$pdb->beginTransaction();
try {
    // 扣库存、扣积分、写兑换记录...
    $pdb->commit();
} catch (\Throwable $e) {
    $pdb->rollBack();
    throw $e;
}
```

**坑（medal 插件实测踩过）**：
- **`$db->begin()` 不存在**——原生 PDO 只有 `beginTransaction()`。写成 `$db->begin()` 会抛 `Error: Call to undefined method PDO::begin()`。
- **catch 内无条件 `rollBack()` 会二次抛异常**：若事务**根本没开启**（如 `beginTransaction()` 本身失败、或误用不存在的 `begin()`），catch 里再调 `rollBack()` 会抛 `PDOException: There is no active transaction`，该异常**逃逸出 catch** → 500 错误页（HTML）→ 前端 AJAX 的 `res.json()` 解析失败 → 用户看到 `network_err` 类网络错误文案（而非业务错误信息）。正确写法：**先 `inTransaction()` 判断再回滚**：

```php
$pdb->beginTransaction();
try {
    // 写操作...
    $pdb->commit();
} catch (\Throwable $e) {
    if ($pdb->inTransaction()) {
        $pdb->rollBack();
    }
    \error_log('MyPlugin error: ' . $e->getMessage());
    return [false, '操作失败']; // 返回业务错误，勿让异常逃逸
}
```

- **AJAX 接口必须保证任何异常路径都返回 JSON**：controller 层若抛出未捕获异常会输出 HTML 错误页，前端 `r.json()` 必然失败。数据库操作务必在插件层 try/catch 消化并返回 `['ok'=>false, 'msg'=>...]`，controller 只负责 `$this->json()` 输出。

### 10.3 SQLite DDL 规则

插件建表必须是 **SQLite 语法**（`ensureSchema` 幂等执行）：

| MySQL 写法（❌ 禁止） | SQLite 等价（✅） |
|---|---|
| `id INT AUTO_INCREMENT PRIMARY KEY` | `id INTEGER PRIMARY KEY` |
| `VARCHAR(n)` / `DATETIME` | `TEXT` |
| `SHOW TABLES LIKE 'x'` 探测 | `CREATE TABLE IF NOT EXISTS`（幂等） |
| `UNIQUE KEY uk (a,b)` | `UNIQUE(a,b)` 或 `CREATE UNIQUE INDEX IF NOT EXISTS` |
| `INDEX idx (a)` | `CREATE INDEX IF NOT EXISTS idx ON t (a)` |
| `NOW()` | PHP `time()` / `date('Y-m-d H:i:s')` 参数绑定 |
| `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` | 直接去掉 |

## 十一、常见坑与红线清单

> 以下全部来自历史审计（`plugins_审计报告.md`、`插件修复报告.md`、`插件性能与索引审计报告.md`）与项目记忆，写插件时逐条自查。

### 11.1 安全红线（一票否决）

> **最高级别红线见第一章"一五、最高级别红线（8 条）"**（反序列化/动态执行、绝对路径、渲染钩子中断、上传白名单、原子扣减、IN 占位符、PDO 属性、AJAX CSRF），违反任一直接不合格，此处不重复罗列。

1. **路径穿越**：文件名必须过 `basename()`（规则 1）。
2. **SQL 注入**：必须预处理 + 参数绑定或 `(int)` 强转（规则 2）。
3. **XSS**：输出必须过 `$this->e()` / `htmlspecialchars()`（规则 3）。
4. **IDOR**：所有按 ID 操作（删除/编辑/兑换）必须校验归属与权限，ID 一律 `(int)` 强转。
5. **CSRF**：写操作（POST 表单）必须带 `csrf` 字段并校验（`Csrf::verifyOrDie()` 或表单隐藏域）。
6. **开放重定向**：`redirect()` 只允许 `/` 开头的相对路径。
7. **上传**：`move_uploaded_file()` 前校验 MIME/扩展名白名单 + `basename()` + 随机文件名。

### 11.2 部署兼容（二级目录 BASE_PATH）

8. 所有前台 URL（链接、表单 action、资源 href/src）必须拼 `BASE_PATH`（`$this->url()` 或 `$bp` 变量），禁止硬编码 `/xxx`。
9. 路由/路径匹配（如 `preg_match('#^/register#')`）要考虑 BASE_PATH 前缀。
10. 资源 URL 加 `?v=filemtime` 版本号。

### 11.3 结构规范

11. **一目录一插件**，目录名小写下划线，命名空间 `Plugin\{首字母大写}` 且与实际文件一致。
12. 钩子文件里**零内联 CSS/JS**，收敛到 `assets/`。
13. 不留 `.bak`/`.revert`/`.tmp` 残留文件。
14. 路由钩子里**不要冗余 `require_once`**（自动加载器已处理）。
15. 登录检查用 `$this->requireLogin()`；404 用 `$this->view('errors/404')`。
16. 建表放 `activate()` + `init_after`（惰性兜底），**不要**在控制器每次请求建表。
17. `uninstall()` 必须清理**所有**相关数据（表、settings 键、用户字段），不留残留。
18. 视图图标用 `$this->icon('名称')`，名称必须在 `TemplateCompiler::$map` 中（如 cart 不存在要用 cart-shopping）。
19. 语言键前缀 `plugin.{插件名}.`；前台交互文案用 `*_act` 后缀。
20. 钩子文件顶部先判空/判模板，避免无关页面白跑。
21. **异常信息不要笼统吞掉**：`catch (\Throwable $e)` 中必须记录真实异常（`error_log($e->getMessage())` 或写入日志 reason 字段），日志原因要可诊断——笼统文案（如一律 "thread not found"）会掩盖根因（ai_assistant 曾因此多轮排查）。
22. **后台弹窗控件样式必须自包含（medal 实测踩过）**：后台视图若把弹窗 DOM 放在 `.admin-container` **之外**（常见写法：视图末尾 `</main></div>` 之后挂 Alpine 弹窗），admin.css 的控件样式全部是 `.admin-content` 作用域（`.form-input` / `.btn` / `label` / `.c-danger` / `.checkbox-inline`），**在弹窗内一律不生效** → 弹窗外框有样式、内部 input/select/按钮裸奔，表现为"弹窗没有样式"（且与缓存无关，加版本号/清 SW 缓存都无效）。正确做法：在插件 `assets/style.css` 里复刻弹窗内控件样式（参考 announcements / medal 整改）——
   ```css
   /* 弹窗 DOM 在 .admin-container 外，admin.css 的 .admin-content 作用域样式不生效 → 弹窗内复刻 */
   .fl-modal .form-input, .fl-modal input.form-input, .fl-modal select.form-input { /* 边框/圆角/内边距 */ }
   .fl-modal .form-input:focus { /* 聚焦高亮 */ }
   .fl-modal .btn { } .fl-modal .btn-primary { } .fl-modal .btn-secondary { }
   .fl-modal .c-danger { color: #ef4444; }
   .fl-modal .checkbox-inline { }
   ```
   自检：弹窗结构写在视图 `</main></div>` 之后 = 一定在作用域外，必须补控件复刻；弹窗写在 `.admin-content` 内部则无需。

### 11.4 性能

21. 避免 N+1 查询：批量查 ID 后一次性 `IN (...)` 补字段。
22. 数据方法做运行时缓存（静态属性），同请求不重复查库。
23. 联表查询注意索引（`ORDER BY` 字段建议建索引）。
24. **每页 Hook 查询上限（量化红线）**：单个插件在一个请求内、所有 `hook/` 触发的数据库查询总和**红线 ≤ 5 次**（轻量校验/查询，不可突破）。需要更重的逻辑（统计、汇总、跨插件联动）一律走 `\app\SplitDB\Queue::push()` 异步，或放到插件自己的独立页面里——不要在 `layout_head_end` / `controller_view_before` 等每页必跑钩子里做重查询。理由：性能审计确认"每页 10+ 条 hook 查询"是页面延迟主因，SplitDB 追求毫秒级响应。
25. 每页 hook 固定查询开销是性能主因——能合并就合并，能缓存就缓存。

**经验补充（来自 ai_assistant 开发，涉及异步与页面性能）**：

26. **自定义任务类型勿塞核心队列**：核心 `cli/worker.php` / `cron_trigger.php` 的消费者只认 `rebuild_search` / `stats`，未知类型会被 `error_log` 后直接标记 done（任务丢失）。插件异步任务用 `\app\SplitDB\Queue::push($type, $data, $queueIndex, $dataPath)` 的**第 4 参 `$dataPath`** 推进**插件自有队列**（如 `plugins/xxx/data/`，.htaccess 已拦 Web），并自带消费端（CLI worker / 钩子触发）。
27. **页面路径零 SQLite（标记短路模式）**：每页必跑的钩子先用**持久化标记**（文件或独立库小表，如 `data/lock/xxx_marker` 或 marker 表）做"有无活"短路——`is_file()` / 单行查表，毫秒级；有活才打开数据库实查。曾因页面路径每次扫 3 个队列文件导致"浏览任何页面都卡"。
28. **时间预算无法中断单个阻塞调用（红线级）**：页面请求内**禁止同步调用外部 API / 网络 IO**（如 AI HTTP 调用 1~10s）。时间预算只在"任务之间"检查，无法中断单个调用——曾设计"小队列同步消费 2s 预算"，单任务仍吃掉 1~10s 阻塞页面。耗时操作必须移出页面进程（后台子进程 / AJAX 分批 / 队列）。
29. **批量消费必须分批（maxTasks 参数）**：全量消费加单批上限参数（如 `drainDue($budget, $all, $maxTasks)`，单批 ≤20），配合时间预算双保险，防大队列一次性卡死（曾 100 任务 × 10s 后台挂死）。

### 11.5 缓存与发布

30. **改插件 hooks 后必须更新 `plugins/plugins_cache.json`**（删除重建或 `Plugin::refresh()`），否则钩子不生效。**精确条件**：仅修改 `plugin.json` 的 `hooks` 清单（新增/删除钩子）需要重建缓存；只改插件代码 / 视图 / 语言包 / assets **不需要**（PHP 即时解释，刷新 OPcache 即可）。
31. **改布局级钩子 / 页脚后需清前台页面缓存**：凡改动 `layout_head_end`、`footer_links` 或任一 `nav_*`（`nav_main_links` / `nav_plugin_links` / `nav_pc_user_links` / `nav_user_menu_items` / `nav_drawer_links`）等影响整站布局输出 / 导航的钩子，或改页脚，修改后都必须 `\app\Helpers\PageCache::invalidate()` 清前台页面缓存（`data/runtime/pages/`），否则访客刷新仍会看到旧缓存里的旧导航 / 脚注。
32. 全部文件 **UTF-8 无 BOM + LF** 行尾；`php -l` 校验。
33. 发布前清理测试数据（如 points_mall 的 CLI 验证脚本只清 `[TEST]` 前缀商品，绝不碰真实数据）。
34. **卸载残留自检**：`uninstall()` 执行后必须自查三处是否干净——① 插件独立库的表已删；② 核心库 `settings` 表里本插件的 key（如 `cr_review_*`）已清；③ `plugins_cache.json` 已由系统重建（无需手动删，但可 `Plugin::getPlugin('插件名')` 确认返回 `null`）。发现残留必须自动清理或明确报错，不能静默放行。
35. **Service Worker 缓存陷阱（红线，零内联插件必看）**：站点启用 `sw.js`，凡同源 GET 若非导航、非 `/api/`、Accept 不含 `text/html`，一律走 **Cache-First**。而 htmx 发请求**不设 Accept**（`*/*`），因此**任何 htmx 局部片段（`HX-Request`）接口都会命中 SW 缓存**——`Cache-Control: no-store` 头会被 SW 拦截、**到不了浏览器**，导致"登录后片段仍显示未登录态 / 改东西必须强刷"，且只能硬刷新绕过。规则：
   - 服务端片段接口务必同时输出 `Cache-Control: no-store, no-cache, must-revalidate`（`header()` 放最先）+ **写操作后 `PageCache::invalidate()`**；
   - 只在 `sw.js` 排除，杜绝 SW 缓存 htmx/动态片段：`if (req.headers.get('HX-Request')) return;`（亦可加具体路径前缀，如 `/floor-reply/`）；
   - 改 `sw.js` 必须递增 `CACHE_VERSION`（**semver 式进位**：从 `flinthub-static-v1.0.0` 起步，改静态资源递增次版本，次版本到 99 进主版本：`v1.0.0 → v1.0.1 → … → v1.0.99 → v1.1.0 → … → v1.99.99 → v2.0.0`），`activate` 才会清掉旧缓存。**教训：任何做 htmx 局部刷新的插件，都要先在 `sw.js` 排查这台缓存**。

### 11.6 插件间通信边界

**插件之间禁止直接耦合**。跨插件数据/动作只允许通过以下两种途径：

1. **核心钩子事件**：如 A 插件发积分后触发 `points_award_after`，B 插件监听该钩子做联动——通过 `Plugin::hook()` 解耦，双方不互相引用。
2. **核心服务**：如 `app\Helpers\Points`、`app\Helpers\Settings` 等核心助手（只读或经核心方法写）。

**禁止**：
- 直接调用其他插件的 `Plugin::db('别的插件名')` 或写其他插件的数据表。
- 直接 `new \Plugin\Other\XxxController` 或调用其他插件的类方法（除非经钩子事件）。
- 跨插件共享数据表——每个插件的数据只属于自己。

**原因**：防止"改 A 插件逻辑把 B 插件弄崩"的连锁反应；插件应可独立启用/禁用/卸载而不影响其他插件。

### 11.7 主题适配（暗夜星辰等现代主题）——样式必须变量化

> 血泪教训：task_center / qa 曾把 CSS 变量名拼错（`--mn-card-bg`、`--mn-muted`），暗夜星辰下永远取不到主题值、回退白底浅字看不清；icon_generator / dice 曾大量硬编码 `#fff` 白底与固定色，深色主题下同样"白卡片 + 浅色文字"失读。修一次浪费数轮。

**核心原则：插件样式一律用 `--mn-*` 主题变量，禁止硬编码颜色（背景、文字、边框、主色）。** 主题只定义 `:root` 变量（如 `assets/css/themes/modern-night.css`），**不会**为插件类补样式——插件必须自己变量化，浅色主题靠 fallback 值兜底，深色主题自动适配。

**正确变量名对照（拼错=静默失效，回退浅色硬编码）：**

| 用途 | ✅ 正确变量 | ❌ 曾写错的写法 |
|---|---|---|
| 卡片/面板背景 | `var(--mn-bg-card, #fff)` | `--mn-card-bg`（不存在） |
| 次要/弱化文字 | `var(--mn-text-muted, #888)` | `--mn-muted`（不存在） |
| 正文文字 | `var(--mn-text, #333)` | `--text-dark`（旧变量，仅兼容） |
| 边框 | `var(--mn-border, #e5e7eb)` / `var(--mn-border-light)` | — |
| 主色 | `var(--mn-primary)` / `var(--mn-primary-subtle)` | 硬编码 `#0066cc` |
| 成功/错误/警告 | `var(--mn-success)` / `var(--mn-error)` / `var(--mn-warning)` | 硬编码 `#67c23a` 等 |
| 提示框语义底色 | `var(--mn-comp-alert-{success,error,warning}-{bg,border,text})` | 硬编码 `#fef3c7` 等 |

**禁止清单（暗夜星辰下全部失读或突兀）：**
- ❌ 硬编码 `background: #fff` 做卡片/按钮/输入框底（深色主题下 = 白卡片 + 主题浅色文字，看不清）；
- ❌ 硬编码 `color: #333/#444/#666/#999`（深底上深字看不清）；文字色必须 `--mn-text` / `--mn-text-secondary` / `--mn-text-muted`；
- ❌ 硬编码主色 `#0066cc`、语义色 `#67c23a/#16a34a/#f59e0b`（hover/active/结果框）——必须用 `--mn-primary`、`--mn-success` 等；
- ❌ 硬编码浅色提示框背景（`#fef3c7` 等）——用 `--mn-comp-alert-warning-*` 系列；
- ❌ 依赖旧版兼容变量 `--primary-color` / `--border-color` / `--text-dark` 新写样式（仅历史插件回退用，新代码一律 `--mn-*`）。

**写法规范：**
- `var(--mn-bg-card, #fff)` 的 **fallback 值 = 浅色主题下的目标色**（如 `#fff`、`#333`、`#e5e7eb`），保证浅色主题零副作用、深色主题自动取主题值；
- 渐变/多段背景同样变量化：`background: var(--mn-comp-alert-success-bg, linear-gradient(135deg, #f0fdf4, #dcfce7))`；
- 主题 CSS 变量全集以 `assets/css/themes/modern-night.css` 与 `assets/css/modern.css` 顶部 `:root` 为准，**写前先 grep 变量名是否存在**（`--mn-card-bg` 这类不存在的一用就废）。

**发布前验证（必做）：**
1. `php -r` 或文本扫描：`grep -nE 'background: *#fff|color: *#[0-9a-fA-F]{3,6}|--mn-card-bg|--mn-muted' plugins/{插件名}/assets/style.css`，命中即返工；
2. 花括号配对检查（`{` 与 `}` 计数相等）；
3. 实机切换「暗夜星辰」主题走查插件前台页：卡片、文字、按钮、结果框、提示框逐一确认可读。**新增/大改插件样式时必须双主题（默认浅色 + 暗夜星辰）各走查一次**。

### 11.8 核心库访问边界（2026-09 双模型交叉裁决落地）

> 以下规则来自《FlintHub 双模型交叉裁决修复实施报告_20260905》（Qwen × MiMo 交叉审计 + 修复），是 2026-09 交叉审计后新增的插件开发约束，写新插件时逐条自查。

1. **禁止直写核心库用户/积分表**（P2 H-4/H-5）：
   - 用户组变更（封禁/解封）→ `(new \app\Models\User())->updateGroupId($uid, $groupId)`；**禁止**直接 `UPDATE users SET group_id = :g`（mod_system 曾直写被审计标记）。
   - 积分扣减 → `\app\Helpers\Points::deduct($userId, $amount, $reason, $refId, $refType)`（条件原子扣减 `AND points >= :p`，防并发负积分，联动等级/缓存/`points_deduct_after` 钩子）；积分增加 → `Points::award()`。**禁止**直接 `UPDATE users SET points = points - :p`（red_packet 曾直写被审计标记）。
2. **禁止原生 SQL 物理删除核心表记录**（P2 M-2）：如删博客评论走 `(new \app\Models\Blog())->deleteComment($id)`，**禁止** `DELETE FROM blog_comments`（mod_system 曾绕过 Model 级联被审计标记）。
3. **批量取用户数据走 `User::batchGetNames()/batchGetUsers()`**（见 10.1，P2 M-1），禁止直查 users 表。
4. **核心 Model `update()` 受 `$fillable` 列白名单约束**（P2-M5）：插件若调用核心 Model（如 `\app\Models\User`）的 `update()`，未列入该模型 `$fillable` 的键会被**忽略并记日志**——不要把请求数组原样传入；敏感字段（role/group_id/status/points）一律走模型专属方法。
5. **积分等级消费走 Points 封装，禁止读 `users.level` 快照做权限判断**（2026-09 审计）：插件消费积分等级统一走 `Points::getSummary()`（单用户权威重算）/ `Auth::getCurrentUser()`（当前登录用户）/ `User::batchGetUsers()`（批量）；读阈值走 `Points::getAllConfigs()`；禁止直接 `SELECT level FROM users` 或拿 `users.level` 快照做"LvN+ 特权"类权限判断——管理员改 `level_config` 阈值后快照失准。完整接口清单见 2026-09 双模型交叉裁决审计报告（独立清单文档 `docs/points_level_api.md` 为待办，尚未建立，文档就绪后再补链接）。

### 11.9 htmx 继承属性污染（hx-push-url / hx-select / hx-target 会传染给子元素）

> 2026-09 thread/show.php + floor_reply 修复沉淀。htmx 的 `hx-*` 属性**沿 DOM 向下继承**：父容器挂了 `hx-push-url="true"` 或 `hx-select="#xxx"`，容器内任何子元素发起的 htmx 请求都会继承这些属性，造成两类典型事故：

1. **整页跳转**：楼中楼回复按钮在 `#replies` 容器（`hx-push-url="true"`）内，点击后按钮自身的 hx 请求继承了 push-url → 响应完成后**整页 URL 跳变**。
2. **响应被过滤**：楼层容器继承了父级的 `hx-select="#replies"`，点赞/操作按钮的 hx 请求响应被按选择器过滤 → 只回填部分 DOM 或什么都不更新。

**修复模板**：
- 需要隔离全部继承属性的嵌套容器，直接加 **`hx-disinherit="*"`**（一劳永逸，不随父级 `hx-*` 属性增删变化）；
- 只覆盖单项的，在子元素加 `hx-push-url="false"` 等反向覆盖。

**自检**：插件在帖子详情（`#replies` 容器内）或其他带 `hx-boost`/`hx-push-url` 的容器内挂按钮/表单时，必须显式加 `hx-disinherit="*"` 或逐项反向覆盖；验证点击后 URL 不变化、响应完整更新。

### 11.10 后台配置页 Tab 标准（复用核心 .admin-tabs，勿自造）

> 2026-09 user_level 后台改造沉淀。插件后台多分区配置页（如 考核指标/徽章/门槛/签到/手动授予）**必须复用核心 admin.css 的 `.admin-tabs` / `.admin-tab-btn`**，不要自定义 tab 类（自定义 `ul-tab` 依赖前台 `--mn-*` 变量，后台环境下变量未定义 → 样式裸奔）。

```html
<div class="admin-tabs" role="tablist">
    <button type="button" class="admin-tab-btn active" data-tab="tab-a" role="tab">A</button>
    <button type="button" class="admin-tab-btn" data-tab="tab-b" role="tab">B</button>
</div>
<!-- 各面板按 data-tab 对应，切换纯 JS，零内联 onclick -->
```

**约定**：
- 切换用纯 JS（读 `data-tab`，`assets/script.js` 里 `addEventListener` 绑定，零内联 `onclick`）；
- 多个表单/分区各自独立提交时，**保存后必须留在当前 tab**（保存前把当前激活 tab 写入 localStorage 或隐藏域，回跳时恢复）；
- 每个 tab 面板内的表单都要带独立 `csrf` 隐藏域。

### 11.11 配置合并：数字键数组必须用 array_replace（嵌套数组逐层处理），禁用 array_merge

> 2026-09 user_level 徽章文案不能保存根因。`array_merge` 对**数字键数组会重新编号**：如 `badge[0..4]` 与默认值合并后变成 `badge[5..9]`，存储的徽章文案键被顶走，读取时永远命中默认空值——表现为"后台保存成功、前台不生效"且无任何报错。字符串键两者行为一致，只有数字键踩雷。

```php
// ❌ array_merge：数字键 0-4 被追加成 5-9，存储值永远读不到
$merged = array_merge($base, $stored);

// ✅ array_replace：按原键覆盖，数字键保持原样
$merged = array_replace($base, $stored);
// 嵌套数组逐层处理：仅当两层都是数组时才 array_replace
foreach ($stored as $k => $v) {
    if (isset($merged[$k]) && is_array($merged[$k]) && is_array($v)) {
        $merged[$k] = array_replace($merged[$k], $v);
    } else {
        $merged[$k] = $v;
    }
}
```

**自检**：插件配置含"按序号数组"（徽章列表、等级文案、档位配置）时，合并函数必须用 `array_replace`；保存→读取→断言值一致。

## 十二、开发流程与验证

1. **建目录骨架**：`plugin.json` + `Plugin.php` + `hook/` + `views/` + `assets/` + `lang/`。
2. **写 plugin.json**：name/version/author/description/activated/hooks/permissions。
3. **写 Plugin.php**：`db()` + `ddl()` + `activate()` + `deactivate()` + `uninstall()` + 业务方法。
4. **写钩子**：按需注册 `init_after`（建表兜底）、`route_register`/`admin_route_register`（路由）、`layout_head_end`（按页加载资源）等。
5. **写控制器/视图**：继承 `Controller`，视图用 `section()` 组织，样式走 `section('css')`。
6. **更新插件缓存**：删除 `plugins/plugins_cache.json` 或调 `Plugin::refresh()`。
7. **验证**：
   - `php -l` 所有新文件；
   - 激活插件 → 独立库建表成功；
   - 前台/后台页面功能走通；
   - **语言键全量比对**：脚本比对视图/控制器用到的 `plugin.{插件名}.*` 键 vs 三个语言包（zh/en/zh_tw），零缺失（曾因缺 `please_select` 键，下拉框直接显示键名原文）；
   - **零内联检查**：`grep -nE '<style|<script>|on(click|change|submit|load)=' plugins/{插件名}/views plugins/{插件名}/hook` 应零命中（`<script src>` 引用除外）；

   - 卸载 → 表删除、无残留；
   - 清页面缓存后抽查首页 `<head>` 无多余资源。
8. **发布**：清理测试数据、删除临时文件、同步 `update/`、更新 `CHANGELOG.md`。

## 十三、给 Agent 的指令模板

> 给 Agent 下插件开发/修改指令时，直接附上以下三段硬性规则，Agent 必须逐条遵守：

**规则 1 — 文件操作，无 basename 不落盘：**
> 任何涉及 `unlink()`、`file_get_contents()`、`file_put_contents()`、`move_uploaded_file()` 的插件代码，必须遵循模板：`$safeName = basename($userInput); if (!$safeName || $safeName !== $userInput) { /* 拦截 */ }`，再拼 `rtrim(UPLOAD_PATH, '/') . DIRECTORY_SEPARATOR . $safeName`。凡是文件名一律过一遍 `basename()`，不允许直接拼接用户输入字符串，彻底摆脱路径穿越隐患。

**规则 2 — 数据库查询，无预处理不执行：**
> 任何 SQL 必须 `prepare()` + `bindValue()` 或 `execute([':id' => intval(...)])`，坚决杜绝字符串拼接；ID 一律 `(int)` 强转防 IDOR。所有查询必须带参数绑定或 `(int)` 强转。

**规则 3 — 入库/出库字符串必须转义：**
> 输出到页面的文字绝不能绕过 `$this->e()` 或 `htmlspecialchars($str, ENT_QUOTES, 'UTF-8')`；入库前按需 `strip_tags()`。TemplateCompiler 已自动转义，但插件控制器/模型层也要自觉做到。

**最高级别红线（8 条，一票否决，违反任一直接不合格）：**
> 1. **禁反序列化/动态执行**：禁止 `unserialize()`（统一 `json_decode($data, true)`）、`eval()`、`assert()`、`preg_replace('/e')`。
> 2. **禁滥用绝对路径**：所有路径基于 `__DIR__` 或 `BASE_PATH`，严禁 `$_SERVER['DOCUMENT_ROOT']`。
> 3. **渲染钩子禁中断页面**：`layout_head_end`/`controller_view_before`/`footer_links`/`nav_*` 内禁止 `die()`/`exit()`/`header()`，必须 `return;`。
> 4. **上传白名单 + 强随机名**：扩展名白名单（如 `['jpg','png','gif']`）+ 重命名 `bin2hex(random_bytes(16)).'.'.$ext`（勿用 `md5(microtime+rand)` 弱随机），禁止保留原始文件名；优先复用核心 `\app\Helpers\Upload::file()`。
> 5. **数量原子扣减**：库存/积分扣减必须 `UPDATE ... SET stock = stock - 1 WHERE id = :id AND stock > 0` 并检查 `rowCount()`，严禁先 SELECT 再 UPDATE。
> 6. **IN 强转 + 占位符**：`$ids = array_map('intval', $ids); $in = implode(',', array_fill(0, count($ids), '?'));`，严禁 implode 拼 SQL。
> 7. **PDO 不覆盖核心属性**：`Plugin::db()` 已由 DBFactory 设 `ERRMODE_EXCEPTION` + `EMULATE_PREPARES=false` + `busy_timeout=5000`，插件不得覆盖；SQLite 无 `ATTR_TIMEOUT`，超时走 `busy_timeout`。
> 8. **AJAX 必带 CSRF**：所有异步 POST 必须携带表单体 `csrf` 字段（惯例，`hx-vals`/`FormData`）或 `X-CSRF-Token` 头，服务端 `Csrf::verifyOrDie()` 校验。

**附加约定（一并附给 Agent）：**
> - 一目录一插件；插件样式/JS 零内联，收敛到插件自己的 `assets/`，不改核心 `admin.css`。
> - 插件独立库用 `\app\Helpers\Plugin::db('插件名')`（原生 PDO），事务用 `beginTransaction()/commit()/rollBack()`，不是 `begin()/commit()`。
> - 插件注册/改动 hooks 后必须手动更新 `plugins/plugins_cache.json`（含 hooks 清单），否则钩子不生效。
> - 视图图标用 `$this->icon('名称')`，名称须在 `app/Core/TemplateCompiler.php` 的 `$map` 中。
> - 改页脚/布局后需 `\app\Helpers\PageCache::invalidate()` 清前台页面缓存。
> - 前台兑换提示用 `*_act` 后缀语言键，无后缀 `err_*` 是后台表单校验文案。
> - 冷却检查用 `$diff >= 0` 保护未来/异常时间戳；删除商品需级联清理关联记录。
> - **生命周期**：`activate()` 必须确保建表成功再返回 `true`（失败返回 `false`/抛异常让系统回滚）；`uninstall()` 顺序 = 先删独立库表 → 再清核心库 settings/用户字段残留 → 缓存由系统自动重建（勿手动删）；`deactivate()` 是临时禁用，**不要删表**。
> - **插件间禁止直耦**：跨插件联动只能经核心钩子事件（如 `points_award_after`）或核心服务（`Points`/`Settings`），禁止调用其他插件的 `Plugin::db()` 或写其数据表。
> - **性能红线**：单个插件每请求所有 hook 的查询总和**≤ 5 次（红线，不可突破）**；重逻辑走 `\app\SplitDB\Queue::push()` 异步或独立页面，禁止在 `layout_head_end`/`controller_view_before` 做重查询。
> - **核心库访问边界（2026-09 交叉裁决新增）**：禁止直写核心库用户/积分表（用户组变更走 `User::updateGroupId()`、积分扣减/增加走 `Points::deduct()/award()`）；禁止原生 SQL 删核心表记录（走 Model 封装，如 `Blog::deleteComment()`）；批量补用户名/用户信息走 `User::batchGetNames()/batchGetUsers()`；调用核心 Model `update()` 受 `$fillable` 列白名单约束，越界键被忽略——不要把请求数组原样传入。
> - **权限声明强制（2026-09 起）**：`permission_enforce` 默认强制，写全局设置需声明 `system:settings`、注册后台路由需 `route:admin`、外部 HTTP 需 `net:fetch`，未声明即 DENY。
> - **卸载自检**：`uninstall()` 后自查——独立库表已删、核心 settings 无本插件 key、`Plugin::getPlugin('插件名')` 返回 `null`，有残留必须清理或报错。
> - **前台 UI 一致性**：PC 下拉菜单插件项复用 `.mn-dropdown-item` 视觉（图标 14px、flex + gap 6px；钩子里 `$this` 不可用，图标用核心字号类 `<i class="fa mn-fs-14">&#xf05e;</i>`，禁内联 `style=`）；插件前台页统一 `.mn-section` 容器；多 tab 前台页每个 tab 都渲染完整导航。
> - **htmx 继承属性污染**：在带 `hx-push-url`/`hx-select`/`hx-target` 的容器（如帖子详情 `#replies`）内挂按钮/表单时，加 `hx-disinherit="*"` 或 `hx-push-url="false"` 隔离，防止整页跳转/响应被过滤。
> - **后台配置页 Tab**：复用核心 `.admin-tabs`/`.admin-tab-btn`（勿自定义 tab 类，后台无 `--mn-*` 变量）；多分区表单保存后留在当前 tab。
> - **配置合并**：数字键数组（徽章/等级列表）合并必须 `array_replace`，禁用 `array_merge`（会重排数字键导致保存值读不到）。
> - **双主题走查**：改插件前台样式后必须双主题（默认浅色 + 暗夜星辰）各走查一次——背景/文字/按钮/结果框/提示框可读性，`.mn-*` 变量生效、无硬编码色（见 §11.7）。
